# 測試慣例

## 命名與結構

- 測試名稱描述**行為**，不是描述函式名
  - ✅ `TestWithdraw_InsufficientBalance_ReturnsError`
  - ❌ `TestWithdraw2`
- 一個測試只驗一件事。需要「順便」多驗一項時，開新的測試
- 用 table-driven test 取代複製貼上的相似案例

## 邊界

- **測試不連外部服務。** 資料庫、HTTP API、訊息佇列一律替換成 fake 或 in-memory 實作
- 不依賴執行順序，任一測試單獨跑都要能過
- 不依賴系統當下時間；時間來源要能注入

## 修改既有測試前先停下來

發現測試擋住你的時候，**先判斷是測試錯還是實作錯**，不要直接改測試讓它通過。

如果結論是測試該改，**在動手前說明理由並取得確認**——這條規則存在的原因是：
「改測試」是最容易讓 bug 溜進 main 的路徑，而且事後從 diff 看起來完全合理。

## 覆蓋率

不追求數字目標。優先補這三類：

1. 有分支的邏輯（`if` / `switch` / early return）
2. 錯誤處理路徑——通常是最少被測、最常出事的地方
3. 修過的 bug——每修一個就補一個能重現它的測試
