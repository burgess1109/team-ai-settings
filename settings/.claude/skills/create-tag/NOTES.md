# create-tag — 設計說明

> 給維護者看的，**不要從 `SKILL.md` 連結這個檔案**。
> 沒有被連結的檔案不會被讀取，所以這些說明完全不佔 context。

## 跟 `mr-create` 的對照

兩份範例刻意採取相反的叫用策略：

| | `mr-create` | `create-tag` |
|---|---|---|
| `disable-model-invocation` | `true` | 不設（預設） |
| `Triggers:` 關鍵字 | 不寫（Claude 讀不到） | 寫 |
| description 是否常駐 | 否 | 是（約一行） |
| 主要防線 | 叫用控制 | 內部確認閘門 |

## 為什麼副作用更大的這個反而開放 AI 叫用？

因為「打個 tag」「建版」是團隊真的會講的話——關掉 AI 叫用等於把最常用的入口拆掉。

防線改由步驟 1、3、5 三道確認承擔。那三道**不管是誰叫用的都有效**，反而比叫用控制更可靠：叫用控制擋不住「使用者主動要求做錯的事」，確認閘門擋得住。

判準不是「有沒有副作用」，是**「需不需要用講的觸發」＋「內部有沒有閘門」**。

## 其他

- `description` 含冒號和逗號，整段必須用單引號包住，否則 YAML 解析會壞掉。
  壞掉時 `/建立 tag` 照樣能用，但 Claude 拿不到 description，自動觸發會整個失效——
  用 `claude --debug` 才看得到 parse error。
- 版號規則如果比「patch +1」複雜（環境 suffix、beta 編號累加），
  建議改寫成 `scripts/next-version.sh`：腳本是**被執行而不是被載入**，不佔 context，
  而且確定性的計算本來就不該交給模型推。
